# Reproducibility and generated data

## Clean macOS setup

Use Python 3.12, `uv`, and Node.js 20.19+ or 22.12+ with npm. The checked-in
`uv.lock` and `apps/twinworld/package-lock.json` pin Python and JavaScript
dependencies. Rasterio wheels bundle the required geospatial libraries; a
separate system GDAL installation should not be needed.

```sh
uv sync --locked --extra dev
uv run uvicorn twinworld.api:app --host 127.0.0.1 --reload
```

The API and UI use the default dependencies. The `dev` extra includes the
test client and STAC dependencies needed by the test suite. Add the
`earthdata` extra for the STAC-based pilot builder without development tools; add `vision`
for DINOv2 inference. These extras are installed together only for workflows
that need both, such as rebuilding the pilot benchmark.

In another terminal:

```sh
cd apps/twinworld
npm ci
npm run dev
```

The service and interface can start without the excluded imagery and embedding
matrix. Visual retrieval requires both the pilot patch rasters and a matching
`artifacts/pilot-100/embeddings_dinov2.npy`; without them the manifest API can
start, but visual search has no populated index and image endpoints cannot
serve absent files. Terrain measurements similarly need the ignored terrain
rasters; their provenance sidecars are checked in.

## Rebuilding the pilot and model features

`data/manifests/pilot-100.jsonl` is the stable record of the current 100-image
pilot, with source URLs, checksums, acquisition metadata, and patch paths.
Generated GeoTIFFs under `data/patches/` are omitted because they are derived
imagery. Rebuild/reacquire the pilot using:

```sh
uv run python scripts/build_pilot.py
```

This downloads source material from the providers declared in
`configs/pilot-sites.json` and records its reproducible plan and patch
manifest. Provider availability, access policies, and network availability
can change. Check each resulting file against its manifest checksum before an
evaluation. The intermediate source downloads live under ignored `data/raw/`.

DINOv2 weights are fetched by Transformers into its user cache when embedding
inference is explicitly run with the vision extra installed. The project uses the immutable model revision
`ed25f3a31f01632728cabb09d1542f84ab7b0056`; the generated matrix and metadata
are stored under ignored `artifacts/`. The current `embeddings_dinov2.json`
records the model, source checksums, preprocessing identity, software
versions, and the prior RTX 3080 CUDA run. Regenerate for the checked-in
manifest and local available device with:

```sh
uv sync --locked --extra dev --extra vision --extra earthdata
uv run python scripts/run_pilot_benchmark.py --model-profile dinov2_small --device auto
```

On Intel or CPU-only Macs, use `--device cpu`; use `--device mps` to select
Apple Silicon acceleration explicitly. To generate a separate 768-D base
artifact, choose `--model-profile dinov2_base`. CUDA is an optional acceleration
path and is not required for setup, tests, API startup, or frontend build. A
CPU/MPS regeneration requires downloading model weights and all manifest
rasters; it may take substantially longer than the recorded CUDA run. Keep the
generated JSON metadata with any generated matrix so its identity remains
auditable.

Terrain GeoTIFFs under `data/terrain/` are downloaded or derived with the
included bounded-window ingestion scripts. Their source, extent, resolution,
coverage and processing provenance are preserved in checked-in `.tif.json`
sidecars. Regenerate an individual context using the observation ID from the
pilot manifest:

```sh
uv run python scripts/ingest_copdem.py --observation <earth-pilot-id>
uv run python scripts/ingest_mola.py --observation <mars-pilot-id>
```

To build the broad Earth GLO-90 sample, use the resumable equal-area pipeline
described in `AUTONOMOUS_DISCOVERY.md`:

```sh
uv run python -m scripts.build_global_earth_contexts \
  --target-count 1000 --candidate-count 20000
uv run python scripts/build_feature_index.py
```

This reads public Copernicus and ESA WorldCover COG ranges; it does not retain
the source tiles. The context manifest records the exact source checksums,
sampling parameters, body-byte transfer counts, context counts, and generated
storage. `--max-storage-bytes` defaults to 5,000,000,000 bytes;
`--max-source-bytes` defaults to 4,000,000,000 bytes and can be adjusted for
the available network budget. An interrupted run resumes from completed contexts
and checkpoints range-response byte counts. The generated 22×22 DEM windows,
WorldCover summaries, SQLite index, and metadata are ignored under
`artifacts/discovery/` and can be regenerated from the source scripts.

The lunar scorecard crop is generated by `scripts/ingest_lola_scorecard.py`; it reads a bounded PDS3 LDEM_64 byte range and writes a provenance sidecar. Its interpolation support is not quantified, and this is not a south-polar LOLA product.

The two small vertical-slice TIFFs in `data/patches/vertical-slice/` are also
generated outputs; rebuild them with `scripts/build_vertical_slice.py` using
the source products and provenance listed in
`data/manifests/vertical-slice.jsonl`.

## Files intentionally excluded

- `data/raw/`: downloaded source products, archives, and temporary acquisition
  files. Reacquire through the data-building and ingestion scripts above.
- `data/patches/**/*.tif` and `data/terrain/**/*.tif`: derived imagery and
  elevation grids. Recreate from source products and manifests/sidecars.
- `artifacts/**/*.npy`, model weight formats, and `models/`/`checkpoints/`:
  reproducible feature matrices, downloaded weights, and model checkpoints.
  Generate embeddings with the pinned DINOv2 revision above.
- `pilot-evaluation.html`: a multi-megabyte, image-embedded benchmark report;
  regenerate by running `scripts/run_pilot_benchmark.py` after preparing its
  input data and annotations. Small machine-readable reports and metadata stay
  tracked.
- Local secrets, `.env` files, virtual environments, `node_modules`, build
  output, compiler/test caches, logs, and temporary/partial downloads.

Manifests, JSON provenance sidecars, configuration, small reports and fixtures,
source, tests, scripts, and both dependency lockfiles remain eligible for Git.
